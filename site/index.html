>> what IS marlin??

marlin is a daemon-native terminal AI agent harness and session multiplexer. Its own agent runs native models; installed Claude Code and Codex agents can run beside it as guests using their existing vendor logins. The daemon owns the structured sessions while the TUI, web UI, and headless CLI remain thin clients.

Close a terminal and the turn keeps running. Reattach later, reach it through SSH, mosh, or your tailnet, or compose it with ordinary shell commands. The transcript, plans, status, approvals, diagnostics, and full tool results are still there—and inspectable without opening SQLite.

GARAGE PICK If Marlin were a car, it would be a first-generation Honda NSX: supercar fast, Honda reliable, usable every day, and direct enough that the driver always knows what the machine is doing. No touchscreen maze, no ornamental controls. Just a small, deliberate machine that starts every time and wants to be driven hard.

  • one native core binary: no Node runtime, no Python environment, no terminal scraping
  • one room for the fleet: Marlin's native agent, Claude Code, and Codex share durable multiplexed sessions without pretending they share an implementation
  • UNIX-shaped clients: run headlessly, list, search, inspect as JSON, archive, kill, and pipe results from ordinary shell scripts
  • append-only truth: context may compact; durable history and full tool output do not pretend they never happened
  • process-boundary extensions: managed MCP stdio servers, executable tools, hooks, and Markdown skills
  • visible execution: durable plans pin the active step and its timing while child work stays inspectable
  • durable review fan-out: delegate two to eight concurrent read-only jobs, or convene a named multi-model council
  • real image input: local clipboard paste and remote-safe path upload stay durable and reach vision models
  • NOT a kitchen sink: marlin is a daily driver. a feature earns its place by surviving daily use, or it gets deleted. the default answer to a new surface is no
DEVELOPMENT PREVIEW Marlin is already self-hosting and useful for real work, but it is not a stable 1.0 product. The native agent, Claude Code and Codex guest sessions, structured multiplexer, scriptable inspection CLI, extension platform, durable plans, child delegation, review councils, SSH remote client, and tailnet web UI are built. Current work is concentrated on hardening edges, diagnostics, and performance. Config and protocol details may still move.

>> take it for a swim

$ curl -fsSL https://marlin.wtf/install.sh | sh
$ export OPENROUTER_API_KEY=...
$ marlin run "why is my build broken"
# ...the daemon keeps the structured session...
$ marlin             # attach the TUI
$ marlin --remote devbox # same TUI, carried over SSH
$ marlin ls          # short stable handles, including children
$ marlin inspect 63df --json # metadata, state, plan, blocks, diagnostics
$ marlin search "permission denied" # search durable transcripts
$ marlin attach 63df # any unique prefix (minimum four)

# installed vendor agents can join the same multiplexer:
$ marlin run --model codex/default "review this patch"

# inside the TUI:
/council new core   # pick models, then choose Done
/review core audit this design before I ship it

The installer downloads the matching tagged release for macOS or Linux on aarch64 or x86_64, verifies its SHA-256 checksum, and installs it in ~/.local/bin without sudo. Homebrew also works: brew install jespern/tap/marlin. Tracking main instead? Clone the repository and run zig build with Zig 0.16.0.

>> edges we're still sharpening (honesty zone)

  • subprocess cancellation: built-in shell and extension processes still need one consistent deadline, TERM, grace, and KILL primitive
  • extension burn-in: MCP and hooks work today; real-world dogfood and exact field-level TOML diagnostics are still active work
  • child hardening: durable batches and cancellation cascade are shipped; disconnect/reconnect and cancellation edges are still being tightened
  • MCP streamable HTTP: stdio is managed and supported today; remote HTTP transport remains later
  • hosted or multi-user web: marlin web is an opt-in, tokenless loopback client exposed through Tailscale Serve; your tailnet is the trust boundary, and it is not a public deploy surface
  • workspace undo/isolation: snapshots, leases, worktrees, /land, and /discard remain one deliberately later track
  • kitchen sink surfaces: no messaging gateway, realtime voice models, wake words, audio protocol, embedded terminal emulator, or dashboard empire; optional local push-to-talk dictation stays entirely at the client edge
